# CleanOS Benchmark Baseline: 2026-08-11 (post-reboot, idle machine)

**Machine:** Mac14,10 M2 Pro (8P + 4E cores, 19 GPU), 16 GB unified memory
**OS:** macOS 26.4.1 (Darwin 25.4, arm64)
**Conditions:** fresh boot, 42 minutes uptime, only the Hermes desktop app and
idle apps running, AC power, ambient room. The previous 20+ day uptime session
(swap up to 14 GB) ended with a reboot on the same morning.
**Date:** 2026-08-11 08:2x local. Single machine, single session, directional
evidence (a reference floor, not a statistical claim).

## 1. Baseline snapshot (Cleanos collect)

`cleanos collect` ran 7 probes with 0 errors. Fresh-boot state:

- Swap used: **0 bytes** (was 7.5-14 GB before the reboot)
- Memory pressure level: 1 (normal)
- Load average: 1.91 / 2.15 / 3.13 (decaying from boot)
- Total RAM 16.00 GiB, compressor 2.07 GiB after idle window
- Findings: orphan_candidate 0, runaway_suspect 0, memory_hog 0,
  duplicate_orphan 0 (honest zero on a clean machine)

## 2. CPU burst: FFmpeg libx264 encode (5 matched runs)

Command: `ffmpeg -y -loglevel error -f lavfi -i testsrc2=size=1920x1080:rate=60:duration=12
-c:v libx264 -preset medium -threads 12 -f null -`

| Run | real | user | sys |
|---|---|---|---|
| 1 | 2.93s | 22.81s | 0.77s |
| 2 | 2.90s | 22.72s | 0.75s |
| 3 | 2.91s | 22.71s | 0.74s |
| 4 | 2.88s | 22.80s | 0.74s |
| 5 | 2.88s | 22.82s | 0.74s |
| **median** | **2.90s** | 22.80s | 0.74s |

Context from 2026-08-10 on the same machine under load (single runs, same
probe): 8.57s real before relief, 4.16s after killing the runaway processes.
The clean baseline is 2.90s: 3x faster than the loaded state.

## 3. CPU sustained: longer encodes

- 60 s input, same settings: real **13.97s**, user 114.03s, sys 3.50s
- 20 s input: real **4.68s** (second run 4.69s), user 37.9s

Parallel efficiency ~7.9x on 12 threads for the burst probe (user/real),
consistent with the encode being thread-bound, not memory-bound.

## 4. Crypto throughput: OpenSSL 3 (brew, -multi 12, 5 s)

| AES-128-GCM | 70.0 GB/s | 74.0 GB/s |

## 5. Memory pressure: 4 GB touched allocation

A 4 GB bytearray with every page touched (1 byte per 16 KB page):

- Pages free before: 209,612 (~3.3 GB) / during: 4,621 (~72 MB) / after
  release: 267,678
- Swap used throughout: **0 bytes** (Swapins 0, Swapouts 0)
- The compressor absorbed the transient; no swap file activity on the fresh
  boot. The same transient on the 20-day session peaked swap at 14 GB.

## 6. Power/thermal envelope (powermetrics, root, during the 20 s encode)

| Sample | P0-cluster | P1-cluster | P-core peak | E-cluster | CPU / GPU / combined |
|---|---|---|---|---|---|
| 1 | 2329 MHz | 2392 MHz | 3329 MHz (CPU 7) | 1945 MHz | 11.0 W / 2.0 W / 13.0 W |
| 2 | 2839 MHz | 2846 MHz | 3467 MHz (CPU 7) | 2186 MHz | (next samples follow) |

All 8 P-cores ran 3109-3467 MHz in the peak sample; E-cores 1864-2186 MHz
active. Package cost of the encode: 13 W combined, far below the 34 W thermal
envelope, so no boost ceiling was hit. On the loaded 2026-08-10 session the
same instrument measured P-cores at 3.0-3.27 GHz: the clean boot sustains
~3.5 GHz at 13 W, a measurable ceiling headroom gain.

## Reproduce

```bash
# baseline snapshot
cleanos collect && cleanos report

# ffmpeg burst (5x)
for i in 1 2 3 4 5; do
  /usr/bin/time -p ffmpeg -y -loglevel error -f lavfi     -i testsrc2=size=1920x1080:rate=60:duration=12     -c:v libx264 -preset medium -threads 12 -f null - 2>&1 | grep real
done

# crypto
/opt/homebrew/opt/openssl@3/bin/openssl speed -evp aes-128-gcm -seconds 5 -multi 12
/opt/homebrew/opt/openssl@3/bin/openssl speed -seconds 5 -multi 12 sha256

# power envelope (root, while an encode runs)
sudo powermetrics -n 8 -i 5000 --samplers cpu_power
```
